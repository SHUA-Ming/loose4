# 系统变更日志

> 目的：让"边走边优化"可复盘。每改一处就记一条，月末按版本分段看胜率，而不是一锅烩。
> 配套：`trade_log.py buy` 会自动给每笔交易打 `CURRENT_SYSVER`（脚本顶部常量）。**改了逻辑就 bump 这个常量，并在这里记一条。**

---

## 记录格式（每条4要素）

```
### vN  YYYY-MM-DD  一句话标题
- 改了什么：具体到文件/函数/阈值（旧值 → 新值）
- 为什么改：触发它的那个观察（哪笔交易/哪天盘面/复现结果）
- 期望：这条改动应该带来什么（更多/更少候选、少踩哪种坑、盈亏比变化）
- 类型：[Bug修复] 立即上 ／ [放松风控] 慎重·最好影子先跑几天
```

## 两档速度（决定该不该立即上）

- **[Bug修复]**：本来就没按设计工作（如 S4 死代码、NaN 换手绕过市值过滤、止损倒挂）。**立即改**，不叫"改策略"。
- **[放松风控]**：松高潮×0.5、松追高门槛、放宽止损、放宽评分门槛等**降低下行保护**的调参。**最容易被最近几天行情骗、在顶部爆掉**。要求：先历史复现证明是真问题 → 最好影子跑几天 → 再正式上。
- **[加严/中性]**：收紧门槛、加排除项、纯展示/记录类。风险低，可较快上。

## 月末怎么用

```
python 工具脚本/50_交易记录/trade_log.py calibration --by version    # 分版本看胜率/盈亏/破纪律
python 工具脚本/50_交易记录/trade_log.py calibration --by strategy
python 工具脚本/50_交易记录/trade_log.py calibration --by mode
```
对比"改动前版本"和"改动后版本"的表现，用你自己的实盘数据决定：这条优化该保留、回滚、还是继续调。

# 变更记录（最新在上）

### 研究记录（非改动·决策留底）  2026-07-02  S4退出「破MA5 vs 到D2」回测 → 维持D2
- 问题：用户提出 D2 硬清仓太死，能否改成"持到破MA5"的趋势型退出让利润奔跑。
- 测法：`scratchpad/bt_s4_exit.py`，S4超集入场(缺概念/龙头两层)10966笔配对比——A(到D2) / B(持到破MA5,D8兜底) / C(赢家才延:D2盈利≥2%且收MA5上才续持)。三者共用下行(破MA5收盘 + 盘中-6%熔断)。
- 结果：未封顶 C 看似最好(均-0.07% vs A-0.13%)；但 **winsorize 封顶@+30%/20% 后 B/C 全面劣于 A**(C -0.26%/-0.47% vs A 稳定 -0.13%)→ C/B 的优势 100% 来自极少数 +50~97% 怪兽单，不稳。A 的胜率(42% vs B29%/C33%)、波动、持有天数、稳健性全面最优；A 期望几乎不随封顶变化=可重复，B/C=靠运气抓龙头。
- 结论：**[否决] 维持 S4 现行 D2 清仓。** "让利润奔跑"在稳健口径下反而更差。现有 D3 豁免(盈利>2%+板块领涨+情绪≥6)已是足够克制的"让赢家跑"，不再放宽。
- caveat：入场是超集(三种退出在此集皆亏→真 alpha 在概念/龙头过滤，不在退出)；单一约400天区间。若日后重议：先补齐入场过滤 + 分区间稳健性再测。
